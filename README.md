# Режус Триптикус 

## UPD: Режим алгоритма 
Так как более качественная работа с PPTX требует наличия PowerPoint
и, соответственно, OS Windows, то предусмотрено два режима работы. 
В .env задаётся параметр `ALGORITHM_TYPE=linux` или `ALGORITHM_TYPE=windows`. 

Если режим `linux` то всё работает через Docker, использует библиотеку python-pptx для дублирования элементов и libreoffice для конвертации в PDF. 

Если режим `windows` то используется PowerPoint (он должен быть установлен в системе) для дублирования слайдов и конвертации в PDF, для удаления и перемещения элементов используется python-pptx. Запуск через Docker невозможен (тк это Windows и надо запускать PowerPoint)! 

## Инструкция по развертыванию и использованию 

1. Скопируйте `.env.example` в `.env` и настройте значения переменных окружения. 
1. Внимательно прочитайте о настройке Telethon (конец этого README.md) и выполните указанные там действия.
1. Запускайте бота через `docker compose up --build` 
1. Сессия Telethon и SQLite база будут лежать в созданной папке-вольюме ./data/

## Система авторизации в боте 

В боте предусмотрена система авторизации. 

1. В .env назначается супердамин, 
1. Чтобы бот запомнил chat_id суперадмина, он должен хотя бы раз зайти в бота и выполнить команду /start 
1. После этого каждый раз, когда в бота заходит новый пользователь, суперадмин будет оповещён об этом. Он сможет `/accept_{id}` и `/reject_{id}` этого нового пользователя. 
1. Кроме суперадмина, в БД в таблице `admins` можно добавить других админов, им также нужно будет написать /start, чтобы бот запомнил айди чата с ними, и после этого они тоже смогут принимать новых пользователей. 
1. Но остальные админы НЕ получают оповещения о новых пользователях, они могут только принимать их вручную. Для этого каждому присоединившемуся пользователю отправляется верная команда `/accept_{id}` для того чтобы он мог переслать её админу. 
1. После принятия пользователь попадает в таблицу `approved_users` и может отправлять презентации. 


Важное замечание: тот пользователь, который выбран как `TELETHON_ADMIN_ID` НЕ может использовать бота по прямому назначению, все присланные им файлы игнорируются. 

### Первоначальная настройка Telethon 

1. Получите API_ID и API_HASH:
    - Зайдите на https://my.telegram.org/auth
    - Войдите с вашим номером телефона
    - Перейдите в "API development tools"
    - Создайте новое приложение
    - Скопируйте API_ID и API_HASH

2. Узнайте ваш Telegram ID:
    - Напишите боту @userinfobot
    - Скопируйте ваш ID

3. Добавьте в .env файл:
   ```
   TELEGRAM_API_ID=ваш_api_id
   TELEGRAM_API_HASH=ваш_api_hash
   TELETHON_ADMIN_ID=ваш_telegram_id
   ```

4. Первый запуск для авторизации:
    - Запустите бота
    - При первой попытке скачать большой файл Telethon попросит авторизацию
    - Введите номер телефона и код подтверждения
    - Сессия сохранится в data/telethon_session

Важно! Если запуск происходит через Docker, то для того,
чтобы первый раз пройти авторизацию (SMS-код), нужно будет подключиться к контейнеру через `docker attach`, ведь ввод происходит через STDIN, а по дефолту в докере он не подключается к терминалу, из-за чего будет возникать ошибка авторизации Telethon.
Команда для подключения к контейнеру в режиме stdin/stdout: 
`docker compose run --rm -it app`

#### Как это работает

Когда пользователь отправляет файл больше 20MB:
1. Бот пересылает файл администратору (TELETHON_ADMIN_ID)
2. Telethon клиент скачивает файл из пересланного сообщения
3. Файл обрабатывается как обычно

После настройки бот сможет скачивать файлы до 2GB!
